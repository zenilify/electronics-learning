# PAPP on the Tab5 — push-to-talk translator firmware (ESP32-P4 · ESP-IDF 6.0.3 · LVGL 9)

Status 2026-11-07 (lane T5): **built and flashed** — see *Verification* at the bottom for what was
measured on Erick's unit and what was not. Showcase target: M5Stack, Shenzhen, Thu 26 Nov.

Hold the left button and speak Spanish/English, or the right button and speak Chinese; release.
The Tab5 sends **one HTTP POST** with the recording to the PAPP backend (`../../server/`), shows the
recognised text and the translation, and plays the translated speech. Every turn shows its latency.


## The one HTTP call (unchanged contract — byte-for-byte `../desktop/papp_client.py`)

```
POST {BASE}/translate?src={es|en|zh}&tgt={es|en|zh}&format=wav&rate=16000
Authorization: Bearer {PAPP_TOKEN}
Content-Type: audio/wav
Content-Length: {44 + n_samples*2}

<RIFF/WAVE header, PCM16, mono, 16000 Hz><samples little-endian>
```

Reply `200 audio/wav` (PCM16 mono, 16 kHz) with `X-Papp-Src-Text` / `X-Papp-Tgt-Text`
(URL-encoded UTF-8, decoded with `unquote` semantics), `X-Papp-Timings` (`{"asr","nmt","tts","total"}` ms)
and `X-Papp-Asr-Model`. Errors: `400` bad audio/lang · `401` token · `413` > 30 s · `502` NVIDIA
upstream down — the firmware keeps the recording and shows **Reintentar · 重试**.

## Endpoints, in the order the firmware tries them

| # | BASE | Works when |
|---|---|---|
| 0 | `http://100.69.244.21:8787` | the Tab5's Wi-Fi is routed into the tailnet (travel router with Tailscale / subnet route) — **the China path** |
| 1 | `http://192.168.1.5:8787` | Toluca LAN — and through the UTR's Teleport tunnel (client NAT; untested) |
| 2 | `https://papp-138753081869.us-central1.run.app` | anywhere Google is reachable (not mainland China); TLS via the IDF CA bundle |

`GET {BASE}/health` with a 2 s timeout at boot, on every Wi-Fi (re)connect, every 20 s while offline
and every 2 min otherwise; the first `200` wins. A transport error during a turn re-probes and retries
once on the next endpoint. The ESP32-P4 has no Tailscale client — do not expose 8787 publicly.

## Features

| | |
|---|---|
| Language pairs | ES ⇄ 中文 · EN ⇄ 中文 · ES ⇄ EN (top bar, remembered in NVS) |
| Push-to-talk | hold = record (ES7210, 16 kHz mono, max 30 s, PSRAM); < 0.45 s = ignored tap; talking interrupts playback |
| Conversation | bubbles left/right per speaker: source text, translation (40 px), latency line; **tap a bubble to replay** (last 24 kept) |
| Status bar | backend endpoint + health RTT, Wi-Fi SSID + RSSI, battery % + charging bolt (INA226 @0x41) |
| Errors | no token / 401 / 413 / 502 / offline each have a bilingual message; retryable ones get a button |
| Demo mode | **▶ DEMO** tap = 5 canned phrases sent through the *live* pipeline (real latency); if no backend answers, each falls back to the embedded reply. **Long-press** = offline-only (no network needed) |
| Boot splash | generic "PAPP" mark with animated voice bars (no third-party logos) |
| Screen | landscape 1280×720 (panel is 720×1280; LVGL rotation via PPA). **Long-press "PAPP"** flips it 180° (NVS) |
| Fonts | Noto Sans SC (OFL) subset, weight 500: GB2312 level-1 hanzi (3,755) + Latin-1 + punctuation + every UI/demo string = 4,092 glyphs, **1.14 MB**, rendered with LVGL `tiny_ttf` at 20–96 px; Montserrat fallback for symbols |

## Provision + flash (cachy, Tab5 on USB-C)

The token and Wi-Fi never enter the source tree or argv. `tools/provision.py` reads
`~/.config/zenilify/papp_token` and `~/esphome/secrets.yaml` on cachy, pipes a CSV into
`nvs_partition_gen` and writes `~/t5/secrets/nvs.bin` (0600). `tools/flash.sh` only talks to the
port `/dev/serial/by-id/…30:ED:A0:E2:EF:41…` (cachy has a second Espressif board on USB).

```bash
ssh cachy
cd ~/t5/src
tools/backup_full.sh LABEL   # full 16 MB read-back -> ~/t5/backup/pdca-<date>/<time>-LABEL/full.bin + sha256 (use this one:
                             # `flash.sh backup` reuses old segments and can glue two firmwares together, found 11-11)
python3 tools/provision.py   # -> ~/t5/secrets/nvs.bin (prints lengths + sha256 prefix only)
tools/flash.sh app           # bootloader @0x2000, partition table @0x8000, app @0x10000 (or: app <foundry dir>)
tools/flash.sh nvs           # token + Wi-Fi @0x9000
tools/flash.sh monitor 40    # boot log
```

Restore the old ESPHome bench console: `esptool write-flash 0 ~/t5/backup/tab5-30eda0e2ef41-full-*.bin`
(or re-flash `tab5-banco` from ESPHome over USB).

Wi-Fi networks provisioned: `wifi0` = home (from the ESPHome secrets), `wifi1` = `zenilify-6E` (the UTR's
2.4 GHz SSID). The C6 radio is **2.4 GHz only**. For China, add the travel router as `wifi2` in
`provision.py` and re-run `provision.py` + `flash.sh nvs` — no rebuild.

## Talking to the running Tab5 from cachy (fw 0.4.2)

The Tab5's USB-C port is its console. `tools/console_nr.py` opens it **without** resetting the board
(`tools/console.py` and `flash.sh monitor|console|bench` do reset it).

```sh
T5=/dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_30:ED:A0:E2:EF:41-if00
python3 tools/console_nr.py $T5 4 0.5:status                 # seconds to listen, then AT:command pairs
python3 tools/screenshot.py /tmp/ajustes.jpg --pre "key a"   # open Ajustes (key a), save what the screen shows
bash    tools/gallery.sh                                     # screenshots of all 13 screens into ~/t5/shots/
python3 tools/ram_walk.py                                    # internal RAM each app costs (opens every app twice)
python3 tools/watch_status.py --every 60                     # `status` into a CSV until `touch ~/t5/watch/STOP`
python3 tools/console_log.py                                 # every console line with the time, plus the CSV; owns the port
echo "status" >> ~/t5/watch/inbox.txt                        # ...so commands go through its inbox while it runs
```

| Command | What it does |
|---|---|
| `status` | Wi-Fi, server, battery, memory, version, uptime, USB-A; `status2` = camera address, dropped frames, UI restarts, speaker volume (`vol=`, 0.4.4); `status3` = charger re-triggers; `status4` = internal RAM: worst-case low-water figure (a sum of per-region minimums, not a moment that happened) and largest free piece; reset reason of this boot (`0x9` = restarted by software, `0x17` = reset over USB, `0x3` = brownout handler or a crash with a digital reset), CPU-only resets caught; since 0.4.3 also `rst=` (ESP-IDF's name for the cause: BROWNOUT, PANIC, WDT, USB ...), `brownouts=` (counted in NVS) and `bod=`; `status3` adds `on_batt=` and `src_changes=` (battery / external power changes since boot). Ajustes shows the cause as "último arranque" |
| `reboot` | restart the Tab5 — a reset of the whole chip (`main/restart.c`). A plain `esp_restart()` can leave Wi-Fi dead on this board and loop forever; the firmware turns every restart into this one |
| `reboot cpu` | test only: restart the way a crash does (CPU-only reset). The next boot must log "full chip reset" and come up normally |
| `bod off` | test only: brownout detector off until the next boot (0.4.3) |
| `mic [seconds [gain dB]]` | what the microphone hears right now, without opening an app: peak and RMS of the samples, two lines per second (full scale 32768). A quiet room reads RMS about 30 at the normal 30 dB; speech at arm's length 130–240. Refused while a recording runs (0.4.4) |
| `subgain <dB> <max>` | test only: input level of live subtitles — analog gain (default 37.5) and largest digital gain (default 12); applies from the next start, not saved (0.4.4) |
| `key <x>` | a key as from the keyboard: `t e f l c a p n d s o r` open the apps, `esc`, `enter` |
| `shot [quality]` | the screen as a JPEG (use `tools/screenshot.py`) |
| `usb on\|off`, `usb`, `usb host` | 5 V of the USB-A port (saved) · what is plugged in · start the USB host stack |
| `chg on\|off` | battery charger (saved) |
| `ext5v on\|off` | 5 V of the Grove port and the M5-Bus (saved, default off) |
| `io` | registers of both I/O expanders, read back from the chips |
| `bcam <ip>\|auto` | set the back camera's address by hand / forget it |
| `wifi <slot>\|auto`, `nets`, `scan` | pick a network (saved) · list the provisioned ones · list what is on the air |
| `sdsync`, `sdsync full` | mirror the server's SD pack; `full` re-hashes every file |
| `remote list`, `remote accept <dev>`, `remote forget` | the remotes |
| `t5b R …`, `t5buart <rx> <tx>\|off` | ESP-NOW bridge input: over this console (bench relay) / on a UART (untested) |
| `uiwd reset` | clear the UI-restart counter |
| `demo`, `say`, `convtest`, `substest`, `c6ver`, `ant`, `tz`, `voice`, `sd`, `camsrc` | as before |

### Live subtitles: when nothing comes up

While Subtítulos runs, the console prints one line per second:

```
subs: chunk 32000 B sent peak 8940 rms 1009 (room noise 45, gain x3.3) -> HTTP 200 in 653 ms, speech open 6.8 s, partial
```

| Part | Meaning | Healthy |
|---|---|---|
| `sent peak / rms` | level of the second of sound that went to the server (after the gain) | speech: RMS 400–3000 |
| `room noise` | quietest 20 ms of the last three seconds, before the gain | 30–80 in a quiet room |
| `gain` | digital gain of this chunk; it puts the room noise at about 150 | 1.5–4 |
| `HTTP … in … ms` | the server's answer and the round trip | 200 in under 1000 ms |
| `speech open` | seconds of speech the server is collecting; 0.0 = it hears no speech | grows while someone talks |
| `partial`, `FINAL` | a grey preview line / a finished caption came back | |

On the screen the same shows as "oyendo voz" (speech open) and, after 8 s without, "no oigo voz: acerca el Tab5 a
quien habla". `mic` (above) tells whether the microphone itself is alive. `substest <1..5>` feeds a built-in clip past
the microphone: if that gives a caption and speech does not, the level is the problem; if neither does, the server is.
The server logs `stream start / final / stop` (`docker logs papp`). History: `docs/PDCA-2026-11-11.md` §7.

## Demo script — M5Stack, Shenzhen (Thu 26 Nov), ~3 minutes

1. **Before the room** (hotel): Tab5 charged; travel router up; check the status bar shows
   `✓ Tailscale` (or `✓ Cloud Run` on roaming data). If it says `✕ offline`, use step 5 only.
2. **Boot** (10 s): the PAPP splash — "push-to-talk translator on the ESP32-P4, Wi-Fi through the
   on-board ESP32-C6, speech AI on our own backend".
3. **Live, Spanish → Chinese**: hold the teal button: *"Hola, mucho gusto. Venimos de México a visitar
   su empresa."* Release. Point at the latency line (≈ 2 s warm).
4. **Live, their turn**: hand them the Tab5, amber side: *"你们想喝点茶吗？"* — the Spanish appears and is spoken.
5. **DEMO** (tap): five canned turns through the live pipeline, both directions plus English.
   If the network dies on stage, the same five play from flash ("demo · offline"). Long-press DEMO to
   force offline from the start.
6. **Talking points**: ES7210 mic array + ES8388 codec via the official Tab5 BSP; LVGL 9 with
   PPA-rotated 1280×720; 4,092-glyph CJK font in 1.1 MB; one plain HTTP POST per turn (works through a
   travel router into a private network); first request after idle can take ~10 s (server warm-up).

Talk 20–30 cm from the top edge (the mics); keep utterances under ~10 s.

**Known issues**

- **Wi-Fi co-processor updated (D-T5-1, 2026-11-07):** the C6 ran factory esp-hosted slave **1.4.1**; it was
  OTA'd from the P4 (`c6ota <url>` on the console, `main/c6ota.c`) to **2.12.13** (1,269,840 B, sha256
  `bfbe138450d88326`). Since then the P4↔C6 SDIO link fails to come up on *some* boots (0x107, host self-resets until a
  good boot) — first blamed on the 40 MHz clock, but it also happened once at 20 MHz, so the cause is **open**
  (landmine 318, retracted claim noted there). Wi-Fi association needs several tries after boot (reason 201), and
  under load there are stalls/drops. The antenna is not the cause: RSSI −47…−57 dBm on the internal antenna.
- **Antennas (schematic p.4):** two MMCX on top. **J15 "External ANT"** = the C6 Wi-Fi radio via an SPDT switch
  (TPG619C6), selected by IO expander 0x43 P0 (low = internal 3D antenna, high = J15). **J16 "EXT. module bypass"** is a
  plain pass-through to an internal IPEX (J14) for an add-on module (Stamp cellular/LoRa) — not Wi-Fi.
  Console `ant ext` / `ant int` stores the choice in NVS and reboots (external with nothing attached = no Wi-Fi;
  `tools/flash.sh nvs` resets it). Console `scan` lists APs.
- **Backlight is on/off only** on this unit: IDF 6.0.3 LEDC faults on P4 rev<3 (landmine 315), see
  `main/p4_rev1_ledc.c`.
- The pre-flash backup has two unreadable regions (landmine 316): 0x1A0000–0x1FFFFF, 0x900000–0x9FFFFF.
  Restore of the old bench console = rebuild `home-lab/esphome/tab5-banco.yaml`.
