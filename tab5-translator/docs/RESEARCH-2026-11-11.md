# Research notes — 2026-11-11 (ESP-NOW on the Tab5 · RainMaker · Tab5 USB-A)

Three read-only research passes run during the overnight PDCA session (`PDCA-2026-11-11.md`). This file keeps the sources.
"UNCONFIRMED" = not found in a primary source. Nothing here was measured unless it says so; the measurements are in the PDCA file.

## 1 · ESP-NOW on the Tab5 (ESP32-P4 host + ESP32-C6 through esp-hosted)

**Verdict: not supported by Espressif** (esp_hosted 2.12.13 … 3.1.0, esp_wifi_remote 1.6.5, IDF 6.0.3 / 6.1).

| Evidence | Source |
|---|---|
| Coverage manifest: `esp_now.h: {unsupported: ESP-NOW is not implemented in hosted}` | https://github.com/espressif/esp-hosted-mcu/blob/v3.1.0/tools/wifi_coverage/wifi_coverage_manifest.yml |
| 2.12.13 lists 112 RPCs, none for ESP-NOW | https://github.com/espressif/esp-hosted-mcu/blob/v2.12.13/docs/implemented_rpcs.md |
| "Support for ESP Now", open since 2024-11-14; Espressif 2025-12-31: "definitely on our roadmap", no date | https://github.com/espressif/esp-hosted-mcu/issues/19 |
| esp_wifi_remote only injects the `esp_now.h` header, no implementation | https://github.com/espressif/esp-wifi-remote/blob/main/components/esp_wifi_remote/CHANGELOG.md |
| Arduino core: `#warning "ESP-NOW is only supported in SoCs with native Wi-Fi support"` under `CONFIG_ESP_HOSTED_ENABLED` | https://github.com/espressif/arduino-esp32/blob/3.3.12/libraries/ESP_NOW/src/ESP32_NOW.h |

**Third-party route (ESPHome, not Espressif):** ESP-NOW runs on the C6 and is forwarded over esp-hosted's CustomRpc
("peer data transfer", `esp_hosted_send_custom_data` / `esp_hosted_register_custom_callback`, since 2.8.1). Verified by
them on "a Tab5 (P4 host + C6 co-processor) and an AtomS3". Needs their C6 image (v2.12.13, same esp-hosted version as
PAPP's host side) plus a host shim (their shim is GPLv3; the slave overlay is Apache-2.0). Limits: fire-and-forget send,
no peer queries, station interface must be up.
https://github.com/esphome/esphome/pull/17712 · https://github.com/esphome/esp-hosted-firmware/tree/main/slave-overlay ·
C6 recovery if a flash goes wrong: https://docs.m5stack.com/en/guide/restore_factory/m5tab5_c6_wifi

**ESP-NOW facts used for the bridge design** (IDF v6.0.3 docs and FAQ):
https://docs.espressif.com/projects/esp-idf/en/v6.0.3/esp32c6/api-reference/network/esp_now.html ·
https://docs.espressif.com/projects/esp-faq/en/latest/application-solution/esp-now.html

- Payload 250 B (v1.0) or 1470 B (v2.0, IDF ≥ 5.4; a v1.0 receiver truncates or drops longer frames).
- 20 peers; encrypted peers default 7 (max 17). Broadcast frames are never encrypted.
- `ESP_NOW_SEND_SUCCESS` only means the MAC layer got an ACK — "It is not guaranteed that application layer can receive
  the data". Use an application ack and a sequence number.
- "the channel of ESP-NOW must be the same as that of the connected AP"; a connected station cannot change channel.
- A receiver in station mode should have modem sleep off.
- Arduino-ESP32 core 3.x: receive callback is `(const esp_now_recv_info_t *info, const uint8_t *data, int len)`;
  pin the channel without an AP with `esp_wifi_set_channel()` after the station interface has started.
- `espressif/esp-now` component 2.5.3 (bind/unbind control, provisioning, security handshake, OTA): calls APIs that do not
  exist on a hosted system, so it does not run on the Tab5 itself.
- Espressif has no official ESP-NOW gateway example ("Gateway" is an open TODO in the esp-now guide).

**Other ways looked at:** Tab5 as SoftAP (supported in 2.12.13, no C6 change); BLE through hosted HCI (open P4+C6 SDIO bug
reports esp-hosted-mcu #204, #212); Wi-Fi Aware / NAN and Thread: not usable with S3 satellites.

## 2 · ESP RainMaker

- **"The new RainMaker" = ESP RainMaker Neo**, announced 2026-08-05: backend (AWS serverless), firmware SDK and app all
  open source. https://developer.espressif.com/blog/2026/08/open-sourcing-esp-rainmaker-neo/ ·
  https://github.com/espressif/esp-rainmaker-neo · docs https://docs.neo.rainmaker.espressif.com
- The earlier product is now **Classic** and still maintained: docs https://docs.rainmaker.espressif.com ·
  firmware https://github.com/espressif/esp-rainmaker · CLI https://github.com/espressif/esp-rainmaker-cli
- **CLIs** (installed on cachy 2026-11-11, isolated venvs): Classic `esp-rainmaker-cli` 1.14.1 (launcher `rmaker`),
  Neo `esp-morpheus` 0.9.0 (launcher `rmaker-neo`; it needs a deployment's `rmng-client-outputs.json`).
  Tokens land in `~/.espressif/rainmaker/` (0700). Never use `login --password` (argv); use `rmaker login` (browser) or
  `rmaker login --user_name <email>` (prompt).
- **Chips:** Neo firmware: esp32 / c2 / c3 / c5 / c6 / s3, IDF ≥ 6.0.2, **no ESP32-P4**. Classic: also P4 with hosted Wi-Fi;
  its camera example has an M5Stack Tab5 overlay. https://github.com/espressif/esp-rainmaker/tree/master/examples/camera
- **Claiming** (how a device gets its cloud identity): assisted (phone app over BLE), self-claiming (S2/C3/S3 per the
  docs), or host-driven with the CLI (`claim <port>`). https://docs.rainmaker.espressif.com/docs/product_overview/concepts/claiming
- **MCP servers:** Classic — local, reuses the CLI's stored login, 13 tools, no credential in argv
  (https://github.com/espressif/esp-rainmaker-mcp). Neo — remote HTTP with OAuth
  (https://docs.neo.rainmaker.espressif.com/docs/cloud-backend/mcp).
- **ESP-NOW + RainMaker:** no glue in either SDK. The only official combination is esp-mesh-lite's RainMaker example
  (group control rebroadcast over ESP-NOW). Pattern for this project: an S3 hub is the RainMaker node and speaks ESP-NOW
  to the others; Neo calls this a bridge node (https://docs.neo.rainmaker.espressif.com/docs/firmware/features/bridge).
- **China:** Classic has a separate China cloud with separate accounts (`https://api2.rainmaker.espressif.com.cn/v1/`).
  Whether the global clouds are reachable from mainland networks: UNCONFIRMED.
- **Cost of adopting it here:** the Tab5 partition table has no factory-data partition and no OTA slots, the camera and the
  remotes neither. RainMaker or any cloud OTA means repartitioning and a USB reflash of each device.

## 3 · Tab5 USB-A power and the I/O expanders

Sources: https://docs.m5stack.com/en/core/Tab5 · schematic
https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1132/Tab5_Schematics_PDF.pdf · M5Tab5-UserDemo
https://github.com/m5stack/M5Tab5-UserDemo (`bsp_io_expander_pi4ioe_init`) · esp-bsp
https://github.com/espressif/esp-bsp/tree/master/bsp/m5stack_tab5 · expander datasheet
https://www.diodes.com/assets/Datasheets/PI4IOE5V6408.pdf

| Expander 0x43 | | Expander 0x44 | |
|---|---|---|---|
| P0 | antenna: low internal / high external | P0 | `WLAN_PWR_EN` (C6 power) |
| P1 | `SPK_EN` | P3 | `USB5V_EN` (USB-A 5 V switch) |
| P2 | `EXT5V_EN` (Grove, M5-Bus, 2.54 header 5 V) | P4 | `PWROFF_PLUSE` |
| P4 / P5 / P6 | LCD / touch / camera reset | P5 | `nCHG_QC_EN` (quick-charge, active low) |
| P7 | headphone detect (input) | P6 / P7 | `CHG_STAT` (input) / `CHG_EN` |

- System I2C: SDA GPIO31, SCL GPIO32. The expanders reset together with the P4.
- USB-A VBUS: U27 MT9700 power switch, enable = `USB5V_EN`, active high, limit about 1.3 A. Its input rail comes from
  USB-C through a 1 A ideal diode (MAX40200) or, with no external power, from the battery through a buck converter.
- M5Stack's firmware raises `WLAN_PWR_EN`, `USB5V_EN` and `CHG_EN` at boot; the Espressif BSP raises none of them by
  itself (`USB5V_EN` only inside `bsp_usb_host_start()`), and its driver leaves every pin **high-Z with a pull-down**
  after its chip reset — a pin needs `esp_io_expander_set_output_mode(.., PUSH_PULL)` before it drives anything.
- USB-A is the P4's high-speed OTG port (internal UTMI PHY); USB-C is the USB-Serial-JTAG port. Both work at once.
- An ESP32-S3's USB-Serial-JTAG is a standard CDC-ACM device (303a:1001) for a USB host
  (https://github.com/espressif/esp-usb/issues/302).
- Third-party report matching our measurement: 0 mA into the battery before, +333 mA after driving `CHG_EN` high on a
  P4 rev 1.3 Tab5 with esp-bsp (https://github.com/armel/uv-k1-k5v3-firmware-custom/pull/783).
- XIAO ESP32S3 Sense as a webcam: about 140 mA average, 347 mA peak at 5 V
  (https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/).
